# required

> **Not an order-profile check.** This is a `JavaScriptCheck`, a distinct
> mechanism used by the admin's table/metadata editing widgets. It attaches
> a client-side non-blank validator to a generated form field; it does not
> run as part of an [OrderProfile](../config/OrderProfile.md) field check.
> See the Notes section for how the two "required" names relate.

Attaches a client-side JavaScript check to a generated admin form field that
blocks submission until the field holds something other than blank or
whitespace-only text.

## Syntax

    js_check=required

Used as a `js_check` option on a form widget generated by the admin UI (for
example a field's `mv_metadata::extended.js_check` setting), not in an
order-profile line. The shipped admin metadata definitions
(`dist/lib/UI/pages/include/meta/mv_metadata.asc`) list it as one of the
available `js_check` values for the `move_combo` field:

    mv_metadata::extended.js_check	move_combo	required=Required,digits=Digits only,money=2 decimal places,no_html=No HTML

## Description

`required` is registered with `CodeDef ... JavaScriptCheck`, a different
registry from the order-check `CodeDef ... OrderCheck` routines documented
elsewhere in this reference. When a form widget is built with a `js_check`
option naming it (`Vend::Form::display`, `lib/Vend/Form.pm`), the routine
runs at page-generation time (server-side Perl, not in the browser) and:

1. Emits a `<script>` block defining a JavaScript function named after the
   field (by default `FORM_flex_editor_FIELD_required`, or derived from the
   widget's `form_name`/`js_check_name` options).
2. Adds an `onBlur` handler calling that function to the field's HTML.

The generated JavaScript function itself runs in the browser when the field
loses focus: it alerts and returns `false` (blocking the blur/submit) if the
value is `undefined`, empty, or matches `/^\s*$/` (whitespace only);
otherwise it returns `true`. The alert messages are built with
[jsq](../admin-tags/jsq.md) (`code/UI_Tag/jsq.coretag`) so they are
properly quoted for inline JavaScript, and are localized error strings
naming the field's label, its internal name, and whether it was undefined,
blank, or whitespace.

## Examples

Register `required` as one of the selectable JavaScript checks for a
metadata field type, as the admin UI's own configuration does:

    mv_metadata::extended.js_check	move_combo	required=Required,digits=Digits only

Attach it directly to a widget's options in a `[display]`/table-editor
context:

    [display table=products name=sku type=text js_check=required]

## Notes

Do not confuse this with the order-profile check-type keyword `required`
used in profile lines such as `fname=required`. That keyword is handled
entirely differently: it is a built-in fallback, `_required` in
`lib/Vend/Order.pm`, dispatched by `Vend::Order::_format` only when no
`&`-directive and no `CodeDef OrderCheck` routine of the same name exists.
There is no `code/OrderCheck/required.oc` file -- the only shipped code
artifact named `required` for a check purpose is this `JavaScriptCheck`,
which serves the admin UI's client-side field validation, a separate
subsystem from order-profile checking.

## Source

Defined in `code/JavaScriptCheck/required.jsc`. The routine takes an option
hash `$opt` (as built by `Vend::Form::display` for a widget) and mutates
`$opt->{prepend}` (to add the `<script>` block) and `$opt->{js}` (to add the
`onBlur` handler). The order-profile keyword of the same name is
implemented separately, as `_required` in `lib/Vend/Order.pm`.
